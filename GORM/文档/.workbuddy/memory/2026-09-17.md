## 环境踩坑记录（下次直接用）

- 本机 Bash 工具的 PATH 是坏的：`dirname`/`tr`/`grep`/`sed` 全部 command not found，curl 也无效。
  → **不要用 Bash 做网络请求或文本处理**，改用 WebFetch 抓网页。
- PowerShell 工具的 stdout **不被捕获**（永远只回 "Command completed with exit code 0"）。
  → 需要输出时让 PowerShell 写文件，再用 Read 工具读。
  但 `Out-File -Encoding utf8` 在 PS 5.1 下会写出 UTF-16，Read 会报 "binary file"；
  → 必须用 `[System.IO.File]::WriteAllText($path, $content, [System.Text.UTF8Encoding]::new($false))`。
- 结论：**抓网页一律走 WebFetch**，这是本环境里唯一稳定可用的通道。

## 补充：Generics API 的 ctx / WithResult + 钩子章节重写

用户追问 `gorm.G[User](db).Create(ctx, &user)` 里的 `ctx` 和 `gorm.WithResult()`，以及钩子的含义/作用/实例。
已把这些内容写进 `文档/GORM创建Create详解.md`（新增 2.3 / 2.4 节，重写第 5 章）。

### 核对源码得到的**重要勘误**（务必记住）

**钩子后置顺序是反的！** 官方 hooks 页面与源码 `callbacks/create.go` 均证实：

```
BeforeSave → BeforeCreate → INSERT → AfterCreate → AfterSave
                                      ^^^^^^^^^^^^ 后钩子先 Create 再 Save
```

即前钩子"Save 在前"，后钩子"Create 在前"，**前后不对称**。
我自己第一版文档写成了 `AfterSave → AfterCreate`，是错的，已在文档和技能里修正。

### 本次核实的源码事实

- `gorm.WithResult()` 返回**未导出类型** `*result`，定义：
  ```go
  type result struct {
      Result       sql.Result
      RowsAffected int64
      Error        error
  }
  func (info *result) ModifyStatement(stmt *Statement) { ...; stmt.Result = info }
  func (result) Build(clause.Builder) {}   // 空实现，只为实现 clause.Expression
  func WithResult() *result { return &result{} }
  ```
  因为类型未导出，**只能**通过 `WithResult()` 构造 —— 这就是它的存在意义。
- `G[T](db, opts ...clause.Expression)` 内部是 `db.Clauses(opts...)`；
  `Clauses` 遇到实现 `StatementModifier` 的参数就调 `ModifyStatement(stmt)`，于是 `stmt.Result = info`。
- 填充点：`callbacks/create.go` 里 `db.Statement.Result.RowsAffected = db.RowsAffected`、`.Result = result`；
  错误由 `gorm.go` 的 `AddError` 填（`if db.Statement.Result != nil { db.Statement.Result.Error = db.Error }`）。
- **PG/SQLite 走 RETURNING 分支时只填 `RowsAffected`，不填 `Result`** → 调用 `result.Result.LastInsertId()` 前必须判空。
- `g[T].apply(ctx)` 实际是 `db.Session(&Session{NewDB: true, Context: ctx}).getInstance()`，
  而 `(*DB).WithContext(ctx)` 就是 `db.Session(&Session{Context: ctx})` → 两者等价。
- `gorm.Config` 有 `DefaultContextTimeout` / `DefaultTransactionTimeout` 两个字段。
- `Config.SkipDefaultTransaction` 的官方注释确认："GORM perform single create, update, delete operations
  in transactions by default to ensure database data integrity"。
- `UpdateColumn`/`UpdateColumns` **不触发 Hook、不更新 UpdatedAt** → 钩子内改计数字段应当用它，避免递归。
