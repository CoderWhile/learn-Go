场景 1 · 钩子里用 tx（正确写法）
========================================================================

-- 事务开始前：计数器 = 0，用户数 = 0
-- 事务内容：① Create 用户（钩子给计数器 +1） ② 返回 error 触发回滚

[0.000ms] [rows:1] SELECT CONNECTION_ID()
-- 事务外的连接 ID = 22

[0.000ms] [rows:1] SELECT CONNECTION_ID()
-- 事务内的连接 ID = 22

[0.000ms] [rows:1] SELECT CONNECTION_ID()

[0.882ms] [rows:1] UPDATE `demo_counters` SET `total`=total + 1 WHERE id = 1

[0.882ms] [rows:1] INSERT INTO `demo_users` (`name`) VALUES ('订单A')

-- 事务返回：后续步骤失败，整个事务回滚
-- 钩子里的连接 ID = 22
   ✅ 钩子与事务是同一条连接（22 == 22）→ 同一事务
-- 事务结束后：计数器 = 0，用户数 = 0
   ✅ 用户被回滚了（=0）
   ✅ 计数器被回滚了（=0）
   👉 两处修改在同一事务里，一起回滚，数据一致。

场景 3 · 「会话级」到底影响谁
========================================================================

-- 3.1 SkipHooks：只影响这一条链，不影响 db 本身

[3.539ms] [rows:1] INSERT INTO `demo_users` (`name`) VALUES ('跳过钩子')
   (a) Session{SkipHooks:true}.Create → 钩子调用次数 = 0（期望 0）

[0.000ms] [rows:1] SELECT CONNECTION_ID()

[0.000ms] [rows:1] UPDATE `demo_counters` SET `total`=total + 1 WHERE id = 1

[4.090ms] [rows:1] INSERT INTO `demo_users` (`name`) VALUES ('正常钩子')
   (b) 紧接着 db.Create            → 钩子调用次数 = 1（期望 1）

-- 3.2 不安全复用：一次使用会「永久污染」这个对象（官方 Bad case）

[3.199ms] [rows:2] INSERT INTO `demo_users` (`name`) VALUES ('会话A'),('会话B')

[0.000ms] [rows:1] SELECT count(*) FROM `demo_users` WHERE name = '会话A' AND name = '会话B'

[0.000ms] [rows:1] SELECT count(*) FROM `demo_users` WHERE name = '会话A' AND name = '会话B'
   第一次(会话A AND 会话B) = 0（期望 0）
   第二次(本以为只剩会话A) = 0（期望 1）
   ❌ 复用后查不到了 —— stmt 被上一次的条件污染了
   对照：一条全新链      = 2

-- 3.3 安全复用：Session(&gorm.Session{}) 让每次派生都独立（官方 Good case）

[0.517ms] [rows:1] SELECT count(*) FROM `demo_users` WHERE name = '会话A' AND name = '会话B'

[0.583ms] [rows:1] SELECT count(*) FROM `demo_users` WHERE name = '会话A'

[0.594ms] [rows:1] SELECT count(*) FROM `demo_users` WHERE name = '会话A'
   第一次(会话A AND 会话B) = 0（期望 0）
   第二次(只剩会话A)       = 1（期望 1）
   第三次(只剩会话A)       = 1（期望 1）
   ✅ base 没被后续调用污染

-- 3.4 Session{NewDB: true} → 丢弃之前累积的条件（官方给钩子的 tx 就是这么造的）

[0.575ms] [rows:1] SELECT count(*) FROM `demo_users` WHERE name = '会话A'

[1.584ms] [rows:1] SELECT count(*) FROM `demo_users`
   原链          = 1（带 name='会话A'）
   NewDB 之后    = 2（条件被清空，全表 2 条）

场景 5 · 批量插入时，钩子里的 tx 会不会跨元素累积条件？
========================================================================

-- 批量插入 3 条，每条在 AfterCreate 里更新「自己那个」计数器
-- 如果 tx 的条件会累积，第 2 条的 WHERE 就会变成 id=1 AND id=2 → 更新 0 行

[0.513ms] [rows:1] UPDATE `demo_counters` SET `total`=10 WHERE id = 1

[0.000ms] [rows:1] UPDATE `demo_counters` SET `total`=20 WHERE id = 2

[0.000ms] [rows:1] UPDATE `demo_counters` SET `total`=30 WHERE id = 3

[4.992ms] [rows:3] INSERT INTO `demo_items` (`name`,`amount`) VALUES ('a',10),('b',20),('c',30)

   counter 1 = 10
   counter 2 = 20
   counter 3 = 30
   ✅ 三条都各更新了自己的计数器 → 没有累积
